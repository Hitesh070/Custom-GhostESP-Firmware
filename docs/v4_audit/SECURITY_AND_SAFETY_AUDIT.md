# Security & Safety Audit (GhostESP God Mode V4)

## 1. Passive-First RF & Safety Controls
- **Default Boot Profile:** Profile `0` (`Combined`) starts passive telemetry (`temp_monitor`), SoftAP (`Hitesh_ESP`), and HTTP/WebUI management without launching OTA floods, beacon spam, deauth storms, or HID keystroke injection.
- **Explicit BadUSB Authorization Gate ([`cmd_badusb.c`](file:///c:/Users/hites/OneDrive/Documents/Projects/Custom%20GhostESP%20Firmware/main/core/commands/cmd_badusb.c)):** Added mandatory `--confirm` argument validation to both `badusb run <script> --confirm` and `badusb exec <size> --confirm`, preventing accidental or unconfirmed HID keystroke injection and warning operators that TinyUSB on `GPIO19/20` detaches Native USB CDC (`COM5`).
- **USB OTG PHY Mutual Exclusion ([`usb_keyboard_manager.c`](file:///c:/Users/hites/OneDrive/Documents/Projects/Custom%20GhostESP%20Firmware/main/managers/usb_keyboard_manager.c), [`badusb_manager.c`](file:///c:/Users/hites/OneDrive/Documents/Projects/Custom%20GhostESP%20Firmware/main/managers/badusb_manager.c)):** Enforced runtime checks across `badusb_manager_start()`, `usb_keyboard_manager_init()`, and `usb_msc_start()` so only one driver may claim the single ESP32-S3 USB OTG PHY (`GPIO19/20`) at a time, eliminating silent driver teardown collisions.
- **Non-Destructive Category D Testing Policy:** Active disruptive commands (`beaconspam`, `dhcpstarve`, `saeflood`, `blespam`, active `deauth`) were audited statically and verified via parser/CLI entry bounds without transmitting disruptive OTA floods onto shared networks.
